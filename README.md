# Расчёт ПЭС ионосферы

[![test](https://github.com/klimovI/diplom2021/actions/workflows/test.yml/badge.svg)](https://github.com/klimovI/diplom2021/actions/workflows/test.yml)

Программа считает полное электронное содержание ионосферы (ПЭС, TEC) на луче от приёмника до спутника GNSS и вызванную им задержку сигнала. ПЭС считается двумя способами: точно, интегрированием вдоль наклонного луча, и приближённо, через вертикальный ПЭС над подионосферной точкой.

## Модель

Ионосфера задана гауссовым по высоте слоем, концентрация в максимуме меняется вдоль трассы. Ниже и выше максимума у слоя может быть разная толщина:

```
N(x, h) = foF2(x)² / 80.8 · exp(−((h − Zm) / W)²),   W = Wm при h < Zm, Wt при h ≥ Zm
```

- `x`: расстояние по дуге от приёмника вдоль поверхности Земли, `h`: высота;
- `foF2(x)`: критическая частота, задана по точкам с шагом `profile_step` и интерполирована квадратичным сплайном (`src/tec/spline.py`);
- `Zm`: высота максимума концентрации, `Wm` и `Wt`: полутолщина слоя ниже и выше максимума.

**Точный способ.** Луч идёт от приёмника под углом возвышения `θ`; `N` интегрируется по длине луча с шагом `step` по дуге до высоты 2000 км.

**Приближённый способ.** Вертикальный ПЭС в подионосферной точке (где луч пересекает высоту `Zm`) интегрируется от 60 до 2000 км с шагом не больше `step` и переводится в наклонный множителем `1 + 16 · (0.53 − θ/180)³`.

Для обоих способов выводятся ПЭС в TECU (10¹⁶ эл/м²), ионосферная задержка `ΔL = 40.26 · TEC / f²` в метрах и в наносекундах.

## Запуск

Нужен только [uv](https://docs.astral.sh/uv/getting-started/installation/), он сам поставит Python 3.11+, других зависимостей нет.

```sh
# Linux, macOS
curl -LsSf https://astral.sh/uv/install.sh | sh
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Расчёт без скачивания репозитория:

```sh
uvx --from git+https://github.com/klimovI/diplom2021 tec --elevation 45
```

В папке репозитория (клон или [zip](https://github.com/klimovI/diplom2021/archive/refs/heads/master.zip)) запускайте `uv run tec …`. Без uv: `pip install .`, затем `tec …`.

## Параметры

Без аргументов `tec` считает пример с параметрами по умолчанию. Любой параметр можно задать флагом, а набор параметров сохранить в TOML-файл; флаги перекрывают файл.

```sh
tec                                         # параметры по умолчанию
tec --elevation 45 --frequency 1227.6       # свои угол и частота (GPS L2)
tec my.toml                                 # параметры из файла
tec my.toml --elevation 60                  # файл, но другой угол
tec --elevation 30,45,60                    # несколько углов за один запуск
tec --elevation 30,45,60 --format csv > tec.csv   # вывод в CSV, есть и json
tec --help                                  # все параметры
```

| Параметр | Флаг | Единицы | По умолчанию | |
|---|---|---|---|---|
| `elevation` | `--elevation` | градусы | 30 | угол возвышения спутника над горизонтом, от 0 до 90; можно несколько: `--elevation 30,45` или `elevation = [30, 45]` |
| `frequency` | `--frequency` | МГц | 1575.42 | рабочая частота (по умолчанию GPS L1) |
| `step` | `--step` | м | 100 | шаг интегрирования по дуге и по высоте |
| `peak_height` | `--peak-height` | км | 300 | высота максимума концентрации электронов, от 60 до 2000 |
| `half_thickness` | `--half-thickness` | км | 100 | полутолщина слоя ниже максимума |
| `top_half_thickness` | `--top-half-thickness` | км | как `half_thickness` | полутолщина слоя выше максимума; `peak_height + 2 · top_half_thickness` не больше 2000 |
| `profile_step` | `--profile-step` | км | 500 | шаг между точками профиля foF2 |
| `profile` | `--profile` | МГц | 4.923 4.84 4.86 5 5.275 5.8 6.22 | критическая частота foF2 вдоль трассы, первая точка над приёмником |

`top_half_thickness` можно не задавать, тогда слой симметричный. Если `half_thickness` взята с ионозонда, верхнюю толщину стоит задать отдельно, см. [сравнение с измерениями](#сравнение-с-измерениями).

Файл с теми же значениями: [`example.toml`](example.toml). Скопируйте его и оставьте только то, что меняете. Имена параметров проверяются: опечатка в файле даст ошибку, а не молчаливое значение по умолчанию.

Профиль должен доходить до точки, где луч поднимается на 2000 км; чем ниже угол, тем дальше эта точка. Если точек не хватает, программа скажет, сколько их нужно.

## Сравнение с измерениями

Профиль foF2 и hmF2 взяли с ионозондов [GIRO](https://giro.uml.edu/) на трассе Юлиусруэ, Прухонице, Рим, Джибильманна (7 дней 2021–2022 годов, 10, 12 и 14 UTC) и сравнили точный ПЭС программы с картой ПЭС [CODE](https://www.aiub.unibe.ch/) и с ПЭС по двухчастотным наблюдениям GPS станции POTS (Потсдам). `Wm` в обоих вариантах взята из параметра ионозонда `B0` (`Wm ≈ B0 / 1.2`), `Wt` подобрана по вертикальному ПЭС CODE над приёмником.

| | Расхождение с CODE | Расхождение с GNSS |
|---|---|---|
| `Wt = Wm` | 47% | 50% |
| `Wt` подобрана | 3.4% | 6.0% |

Ионозонд видит только нижнюю часть слоя, поэтому с одной толщиной ПЭС выходит почти вдвое меньше реального. С отдельной толщиной верхней части расхождение падает до нескольких процентов.

Данные ионозондов: Global Ionosphere Radio Observatory; Reinisch, B. W., and I. A. Galkin, *Global ionospheric radio observatory (GIRO)*, Earth, Planets and Space, 63, 377–381, [doi:10.5047/eps.2011.03.001](https://doi.org/10.5047/eps.2011.03.001), 2011; http://spase.info/SMWG/Observatory/GIRO. Станции: Juliusruh (JR055, Leibniz-Institut für Atmosphärenphysik), Pruhonice (PQ052, Institute of Atmospheric Physics CAS), Rome (RO041) и Gibilmanna (GM037), обе станции Istituto Nazionale di Geofisica e Vulcanologia. Карты ПЭС: Center for Orbit Determination in Europe (CODE), Astronomical Institute, University of Bern. Наблюдения GNSS: станция IGS POTS (GFZ Helmholtz Centre for Geosciences), архив BKG GNSS Data Center; Johnston, G., A. Riddell, and G. Hausler, *The International GNSS Service*, Springer Handbook of Global Navigation Satellite Systems, 967–982, [doi:10.1007/978-3-319-42928-1_33](https://doi.org/10.1007/978-3-319-42928-1_33), 2017.

python -m unittest discover -s tests
